# 预算锁 Encumber

**Agent 团队的链上项目预算：被预占的钱谁也挪不走，已调走的钱 Agent 也花不了，账始终对得上。**

Monad Blitz 广州（2026-11-21）参赛项目 · 运行在 Monad 测试网

- 🌐 在线控制台：https://hold-the-screen.vercel.app
- 📜 合约：[`0x27edaccb77ac3ac96a2905dc44cd14e26e22c4c8`](https://testnet.monadvision.com/address/0x27edaccb77ac3ac96a2905dc44cd14e26e22c4c8)（MonadVision、Monadscan 源码已验证）

## 解决什么问题

越来越多公司让 AI Agent 自己付费调用外部服务（大模型、数据接口）。一个团队往往同时跑多个项目、每个项目挂几个 Agent，财务还会在项目之间调拨预算。于是出现三个问题：

1. **同一笔钱被承诺两次**：财务正把甲项目剩下的钱调给乙，甲的 Agent 同时在花这笔钱，两边都以为钱是自己的，结果超支。
2. **按量计费没法直接付**：大模型按 token 计费，花多少事先不知道；x402 这类协议要求固定价格。
3. **月底才发现账对不上**：传统做法靠事后对账，发现问题时钱早就花出去了。

## 怎么解决

每个项目的预算被合约拆成三种状态，实时维护：

| 状态       | 含义                                     |
| ---------- | ---------------------------------------- |
| **已花**   | 已经付给服务商，永远留在原项目的账上     |
| **已预占** | Agent 已为某个任务锁住，结算前谁也挪不走 |
| **可用**   | 只有这部分能被花掉或调拨                 |

规则：

- **预占 → 结算 → 释放**：Agent 调用按量计费的服务前，先预占一个上限；完成后按实际花费结算，剩余自动释放回项目（解决按量计费无法用固定价格付款的问题）。
- **调拨只动“可用”**：财务调拨只能调走“未花且未预占”的部分。
- **并发时按链上顺序判定**：付款和调拨同时发生，先上链的成功，后上链的被拒。
- **拒绝也上链**：被拦下的付款和调拨不 revert，而是写入一条带原因的 `Rejected` 事件和链上活动记录（“这笔钱已被预占”“可用余额不足”……），客户和审计方自己就能查。

## 演示（控制台首页一张表 + 三幕）

| 幕   | 操作                                                | 结果                                                    |
| ---- | --------------------------------------------------- | ------------------------------------------------------- |
| 准备 | 团队预算 0.1，甲 0.06、乙 0.04；乙花完，甲只剩 0.02 |                                                         |
| 一   | 客服 Agent 预占 0.02 → 财务想把这 0.02 调给乙       | ⛔ 调拨被拦：“这笔钱已被预占”                           |
| 二   | Agent 按实际 0.012 结算 → 财务调拨释放出来的 0.008  | ✅ 剩余 0.008 自动释放并成功调给乙；已花的 0.052 留在甲 |
| 三   | Agent 付款 0.02 和财务调拨 0.02 **同时提交**        | 先上链的成功，另一笔被拒；两种顺序结果都对得上账        |

**测试网实测**（2026-11-21）：付款先发时，两笔交易落在**同一个区块 81513863**，付款是第 9 笔（成功），调拨是第 10 笔（被拒：可用余额不足）；调拨先发时，调拨在区块 81513793 成功，付款在下一个区块被拒。

## 和已有项目的区别

| 项目                                 | 做了什么                                       | 区别                                               |
| ------------------------------------ | ---------------------------------------------- | -------------------------------------------------- |
| SDWallet（Monad Blitz 杭州 V2 冠军） | 单个 Agent 的单笔 / 每日限额、收款白名单、x402 | 只有一个资金池，没有项目层和调拨                   |
| SmartBudget（杭州 V2）               | 单笔 / 每日 / 每周限额                         | 预算仍是一个池子，财务挪不走，也不能占住正在花的钱 |
| TaskPay、Bursar、OpenAgentPay        | 任务预算、拒付事件、链下分级预算               | 没有把项目间调拨和 Agent 预占放进同一个链上账本    |

**Encumber 的切入点：把“财务调拨”和“Agent 预占”放进同一个链上账本，由合约强制执行，并发下也对得上账。**

## 为什么在链上、为什么是 Monad

- **账本归谁改**：财务和 Agent 都绕不过合约，被拒的操作带原因留在链上，第三方不需要信任服务商的服务器。
- **高频小额**：Agent 每调用一次服务就付一次钱，需要亚秒确认和极低手续费；300ms 出块让控制台上的预算状态几乎实时。

## 谁会用、怎么收费

- 帮多个客户运行 AI Agent 的自动化服务商：每个客户、每个项目的钱必须分得清。
- 大量使用 Agent 的公司财务：按项目控制和核算 Agent 支出。
- 收费设想：按团队收控制台订阅费；按结算笔数收少量服务费（待验证）。

| 部分     | 内容                                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- |
