# 预算锁 Encumber

**Agent 团队的链上项目预算：Agent 锁款后，供应商凭链上承诺就敢开工；Agent 掉线、财务想挪钱，都动不了这笔承诺，账始终对得上。**

- 🌐 在线控制台：https://hold-the-screen.vercel.app （公开访问为只读；演示操作需要口令）
- 📜 合约：[`0x58caf471a5b2cdc3f0151e731c1f9fc1043937b8`](https://testnet.monadvision.com/address/0x58caf471a5b2cdc3f0151e731c1f9fc1043937b8)（MonadVision、Monadscan 源码已验证）

## 解决什么问题

越来越多公司让 AI Agent 自己付费调用外部服务（大模型、数据接口、算力）。一个团队往往同时跑多个项目、每个项目挂几个 Agent，财务还会在项目之间调拨预算。于是出现三个问题：

1. **供应商不敢开工**：按量计费的服务事先不知道要花多少。供应商看到 Agent 下单，却不确定事后能不能收到钱。Agent 掉线了、财务把预算挪走了，钱就没了着落。
2. **同一笔钱被承诺两次**：财务正把甲项目剩下的钱调给乙，甲的 Agent 同时在花这笔钱，两边都以为钱是自己的，结果超支。
3. **月底才发现账对不上**：传统做法靠事后对账，发现问题时钱早就花出去了。

## 怎么解决

每个项目的预算被合约拆成三种状态，实时维护：

| 状态       | 含义                                           |
| ---------- | ---------------------------------------------- |
| **已花**   | 已经付给供应商，永远留在原项目的账上           |
| **已预占** | 已锁定为某个供应商的付款承诺，到期前谁也挪不走 |
| **可用**   | 只有这部分能被花掉或调拨                       |

核心规则：

- **锁款即承诺**：Agent 锁定一笔上限，绑定**指定供应商、订单号和截止时间**。供应商在链上看到 `Committed` 事件就可以开工。
- **供应商独立兑现**：截止前**只有指定供应商**能按实际用量结算，金额不得超过上限，每笔承诺只能结算一次。结算时供应商到账，剩余**在同一笔交易里**自动回到项目可用余额。
- **谁也取消不了**：承诺到期前，Agent 和财务都不能取消；过期未结算的才能被任何人释放。
- **调拨只动“可用”**：财务调拨只能调走“未花且未预占”的部分。
- **并发时按链上顺序判定**：付款和调拨同时发生，先上链的成功，后上链的被拒。
- **拒绝也上链**：被拦下的操作不 revert，而是写入一条带原因的 `Rejected` 事件和链上活动记录（“承诺还没到期，谁也取消不了”“这笔钱已被预占”“可用余额不足”……），客户和审计方自己就能查。

## 和已有项目的区别

| 项目                                 | 做了什么                                       | 区别                                                                       |
| ------------------------------------ | ---------------------------------------------- | -------------------------------------------------------------------------- |
| SDWallet（Monad Blitz 杭州 V2 冠军） | 单个 Agent 的单笔 / 每日限额、收款白名单、x402 | 只有一个资金池，没有项目层、调拨和供应商承诺                               |
| SmartBudget（杭州 V2）               | 单笔 / 每日 / 每周限额                         | 预算仍是一个池子，财务挪不走，也不能占住正在花的钱                         |
| x402 `upto` 方案                     | 先授权上限、再按实际用量结算                   | 是单次支付层面的预授权；没有项目预算、财务调拨和“到期前谁也取消不了”的承诺 |
| TaskPay、Bursar、OpenAgentPay        | 任务预算、拒付事件、链下分级预算               | 没有把供应商收款承诺和项目间调拨放进同一个链上账本                         |

**Encumber 的切入点：供应商的收款承诺和财务的预算调拨，由同一个项目金库强制执行。**

## 为什么在链上、为什么是 Monad

- **账本归谁改**：财务、Agent、供应商都绕不过合约。供应商不需要信任 Agent 或服务商的服务器，看到链上承诺就能开工；被拒的操作带原因留在链上，第三方自己就能查。
- **高频小额**：Agent 每调用一次服务就锁一次款、结一次账，需要亚秒确认和极低手续费；300ms 出块让控制台上的预算状态几乎实时。

## 谁会用、怎么收费

- 帮多个客户运行 AI Agent 的自动化服务商：每个客户、每个项目的钱必须分得清。
- 按量计费的外部数据、算力、大模型供应商：凭链上承诺决定是否开工。
- 收费设想：按团队收控制台订阅费；按结算笔数收少量服务费（待验证）。

## 技术实现

| 部分     | 内容                                                                                                                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 合约     | `contracts/src/Encumber.sol`，Solidity 0.8 + Foundry，13 个测试（供应商独立结算、只有指定供应商能结算、不超上限、只能结算一次、到期前谁也取消不了、过期可释放、两种先后顺序、已花留在原项目、金库余额守恒） |
